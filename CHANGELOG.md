# Changelog

What changed, why, and how it was checked (and what was not). The pages of `docs/` describe how things are; this file says how they came to be. Unless an entry says otherwise it was checked with `spotlessCheck`, the unit tests and `lintDebug`, and on the emulator against the fictional server of the user guide (`docs/user-guide/fake-backend`), not against a real OpenMRS.

## Unreleased

### Fixes

- **Group sessions lost the answers of the patients who were submitted before the last one** (`GroupFormEntryFragment`): the first fix of this kind covered only the last patient. When **Submit** was pressed on any other patient the app moved to the next tab by selecting it, which read the form it left (twice) and kept the answer; a submitted form answers with only its first questions, so the patient lost everything after them, the groups of questions 10 and 11 of the Activity form included, while patients moved between with the tabs were saved whole: some patients saved well and others did not. The tab is now changed with the guard on (nothing is read) and the submitted form is dropped, so that coming back to the patient builds it again from the kept answers; when the final check finds patients to complete, the form on the screen is built again. Checked on the emulator in a group session of two patients with the GAD-7 form (a comment on its last page for each): the answers of the first patient, submitted then left, and of the last were both saved. Not checked: the Activity form itself in a session (the mechanism does not depend on the form), four patients or more.
- **A patient list the server said yes to, but did not create, was reported as sent and then vanished** (`PatientListsRepository`, `ApiManager.write`, `ServerChecks.writeTest`): a `PUT` answered 2xx was taken as proof; the list then left the device at the next read of the server's lists, and nothing was logged. Now the list is read back after every create and edit the server accepts: one that is not there stays on the device as **Not accepted by the server** with the reason "The server said yes but did not create the patient list" (an edit the server did not keep: "did not keep the change"), and "Send now" tries again; a server that cannot be asked afterwards leaves the change to go again. A write answered with a web page (a gateway) is not a yes. What the server kept of a create (name, description, location, cohort type) is compared with what was sent. Every request about a patient list is logged (`Patient list create <id>: answer=...`, with the code and the reason, in the file log of the diagnostics report) and recorded in the audit trail (`PATIENT_LIST_SENT`). The **Test writing** check reads the list back too. The fake server has a `silent-writes` scenario. Tests: a create and an edit the server accepts and does not keep, and a create whose answer cannot be checked. Checked on the emulator against the fake server: a list is created, read back and kept; with `silent-writes` it stays as "Not accepted by the server". Not checked: **a real OpenMRS** (the server of the report was not reachable: why it says yes and keeps nothing is not known yet), and editing from the emulator by hand.
- **Forms in the dark theme were lavender and pink** (`values-night/styles.xml`, `Questionnaire` style): the dark `AppTheme` was a full copy of the light one without `questionnaire_theme`, so the form library fell back to its own Material 3 theme: lavender buttons and selected answers, a pink "This question is required". The dark theme now names the app's form style, and that style also sets the error, green and secondary-container colours, so no stock colour is left (errors are the app's red). Checked on the emulator in dark mode with the GAD-7 form: teal Next button and radio buttons, red required message; the light theme is unchanged. Not checked: the colour-blind palette in the dark theme.
- **A patient list is ticked only with its checkbox** (`SelectPatientListItemRow`): a tap anywhere on the row ticked the list and so downloaded its patients. Now only the checkbox does; the arrow still opens the list. Test: `tappingTheRowOfAPatientListDoesNotTickIt`. Checked on the emulator: a tap on the row changes nothing, the checkbox ticks. No tutorial step changes (it already says to tick).
- **Pending changes were unreadable in the dark theme** (`UnsyncedRows`): the rows of observations are a see-through tint and did not set the text colour, so the title was the default black on dark. Every row now sets its colours. Checked on the emulator (dark) with a patient to identify, its encounter and its observations.
- **The Review button of the sync page seemed to do nothing** (`SyncScreen`, `UnsyncedResourcesScreen`): it only selected the Pending tab, which is the tab already open when a patient waits to be identified. It now also scrolls to the patients to identify and lights them for a moment. Test: `reviewShowsThePatientsToIdentify`. Checked on the emulator: the row is lit after the tap. Not checked: a list long enough to scroll (the scroll is `animateScrollToItem(0)`).

### Patient lists

- **Create, rename, delete and fill patient lists, offline first.** The Patient lists screen both chooses what the device downloads and manages the lists: a list opens to its details and members, which can be added (from the device or the server) and removed. Changes are saved on the device at once, marked as waiting, and sent after a sync, with the live upload or with **Send now**. They live in their own tables because the SDK uploads an update as a patch, which the server refuses for a Group. Members are sent as `$add-members` / `$remove-members`; a create is a `PUT` of the id chosen on the device, so a lost answer is safe to repeat; a refused change keeps its reason and is not retried by itself. The server side is the `openmrs-module-fhir2extension` module (`feat/group-patient-lists`). The app says *patient list*, FHIR says `Group`, *cohort* stays on the OpenMRS side. Checked: repository, overlay and mapping unit tests, the module's 36 tests, `contract_check.py` against the fake server, and the screens on the emulator. Not checked: **a real OpenMRS** (the module was never deployed), two devices on one list, thousands of members, French / Spanish / Arabic.
- **Lists in other screens.** A patient's page shows the lists the patient is in and **Manage** ticks them; the Patients screen can be limited to one list; a patient to identify later can be put in a list (the add is held until they are identified). A **group session starts from one list**: only downloaded lists are offered, the participants are the list's patients (untick the absent, add others, create a new patient, identify later) and the added ones join the list when the session starts. Each encounter records the session's list in the two internal observations; the concept ids are now in `<group-sessions>` of `app_config.xml`. In live mode a session and the Patients filter can also find and download patients that are only on the server. The session details form can no longer be submitted with required answers missing. Not checked on a device: the join of a patient from outside the list at Start, resuming a session from a draft, the patient page dialog.
- **A patient registered on the device and not uploaded can join a list.** The add is held ("Waiting for the upload") and follows the id the server gives, read from the upload's own answer (`UploadedIds`); only without it is the patient looked for by name, birth date and sex, and several matches are never guessed (the add stays, marked, for the user to redo). Not checked against a real server.
- **Registering into a list, bulk adds, history and export.** Registering a patient from a list's filter or picker adds them to that list; the picker has **Select all** and **Add the members of another list**; a list has **History** (who did what, last 500 events) and **Export** (CSV through the share sheet, with a warning, formula-safe, audited without names). Not checked on a device: the bulk actions, the CSV in a spreadsheet, the history dialog.
- **Lists without a session, and always with all their fields.** A guest manages lists like anyone; their changes are adopted by the user who signs in. A list created without a location gets the one chosen later (on picking it, on completing guest data, and whenever the lists are sent), and is not sent until it has one. A created list is sent with name, description, location and the configured cohort type. Not checked: signing in afterwards on a device, a real server.
- **Several users on one device.** Changes to lists, group-session drafts and patients to identify belong to the user who made them, and only that user sees and sends them; "Delete patient data" removes only theirs. Not checked by hand with two users.

### Server compatibility

- **Settings > Advanced settings > server checks.** A server without what the app needs (writable patient lists, the two group-session concepts) used to fail late, with a refused write or encounter. The page lists what the server supports (sign-in, FHIR R4, lists readable, members addable, Cohort Module, the concepts), with what the app does without it. **Test writing** (confirmed first) creates and deletes one temporary list; **Copy the report** is for whoever supports the server. What is not supported is left out (lists become read only, an observation with a missing concept is not recorded), and a clear refusal marks the feature unsupported at once. Nothing waits for a check. The settings for administrators now sit in one closed **Advanced settings** section. Not checked: a real OpenMRS (the answers are assumed from HAPI), French / Spanish / Russian / Arabic and 320 dp.
- **The checks can be turned off** with `<server-compatibility enabled="false" />`: the page and its summary are hidden, nothing is checked, every feature is offered.

### Forms

- **Forms on the server (Settings > Advanced settings).** The app keeps using its own forms by default, and the user can now see which of them differ from the server's (up to date, update, new, not on the server) and update the ones they choose, or go back to the app's version. Replaces the old "fetch questionnaires" button. Checked on the emulator against a fake server serving forms, and with unit tests. Not checked against a real server.
- **Group sessions saved only the first answers of the last patient**, so the groups of questions 10 and 11 of the Activity form (and everything after the type of activity) were missing. Pressing Submit read the form a second time, and the library returns only the first answers of a submitted form; the last patient's answers are no longer read again. Found and checked on the emulator by saving a session and reading the observations back. Not checked: several patients in one session, a session resumed from a draft.
- **Activity form.** A new activity type, "Commemoration / memorialization event", opens and closes the same questions as "MHPSS Specific moment (Colombia)". The form was also brought in line with the ampath web form (the missing question 9, a calculated training total, the training name, required target group and 0 to 99999 counts, a missing observation link, the reporting note, two lists of activity types for emergency yes / no). Checked on the emulator by saving and reading back several activity types; not checked: Training online, Supervision online, the emergency single session. Not done: the web "provider" question.
- **Numbers are no longer rewritten when a form is expanded** (`45.0` became `45`, `1.50` became `1.5`, long decimals lost digits); a unit test now compares every bundled form.
- **Smaller form changes.** "Psychiatric care" referral option in the Assessment and Follow-up forms; the Assessment option is now "Health ICRC"; the duplicate DASS-21 form is removed. New **Minimum Data Form** (ten pages, five languages; its encounter type code is still to add). A bundled form saved with line breaks was not expanded; an encounter whose question has both a starting value and an initial expression could not be edited; children of the same question under different parents all went to the first parent (encounters saved before keep theirs until edited again).
- **Registration:** the default registration form's gender was dropped on save (the server refused the patient); first and family name no longer end up at the bottom of page 1; paged forms no longer show a blank gap between pages in the review.
- **The app crashed when it was left and resumed during a form**, and the work was lost (`TransactionTooLargeException`: the form library kept the whole questionnaire twice in the saved state, 710 KB). The questionnaire is now written to a file and the library gets its address. Reproduced and checked on the emulator. Not checked: a restore after the system killed the process.
- **Group session form drawn twice**, because the lookup by tag ran before the transaction was applied; live forms are now tracked in a map.
- **Page breadcrumbs** in paginated forms: a row above the progress bar lists the pages and a tap jumps to one; going forward is blocked at the first page with a required answer missing.

### Sync and data

- **The patient download never finished on a real network** and could not find new data of patients already downloaded. One search asked for patients with all their encounters and observations (`_revinclude`), which the server cannot page: a page of ten patients was almost 2 MB and 25 s, and the sync was cut and restarted 16 times. Now the patients of the lists come first, then patients, encounters and observations ten patients at a time, 50 a page. Each patient carries the time its data is complete up to, saved page by page, so a cut loses at most a page and new encounters of a known patient are found. A sync stopped by WorkManager now logs why (`stop_reason`). Checked with unit tests against a fake server and against the test server with 150 lists selected, cut and restarted. Not checked: the phone where it happened, a slow server behind a proxy. An update from an older version downloads everything once more.
- **An encounter deleted on the server is removed from the device** after a sync or a pull to refresh, only when the server answers 404 or 410 for it, and never what waits for upload. Checked with 8 unit tests and on the emulator. Not checked: a real OpenMRS (its answer for a voided encounter is assumed), a device with thousands of encounters.
- **Patient search with a given and a family name** now works: the typed space was trimmed away and a two-word search matched nothing. Every word must match the name, on the device and on the server. Not checked: a real OpenMRS (repeated `name` parameters are assumed to be ANDed).
- **No periodic sync in live mode**: the countdown does not run while live mode sends what is saved at once.
- **Test connection:** a redirect counts as reaching the server (a server behind a single sign-on gateway was reported as "unexpected answer").
- **Patient list search race:** only the latest search publishes, and a failure no longer leaves the screen loading. The diagnostics export and the sync-info worker no longer run on the main thread or leak their scope.

### Home, sync page and tutorial

- **"Everything is uploaded" is no longer said while something waits for the user.** A patient to identify shows an "Action needed" card on the Sync page and a tonal notice instead of yellow text, and the Home pill says what is waiting. The separate "Patients to identify" card is gone: the pending tab lists those patients, each with **Identify now**. Not checked: the long languages at 1.3 times font scale on a small screen.
- **Tutorial:** steps follow the screen order, start only when the data is loaded, and have a Back button.
- **Settings page** regrouped into Language and appearance, General and security, Forms, visits and identifiers, and the rest.
- **Recent patients:** a section above "All patients" with the patients the user worked with last. After registering, the app opens the patient's page; the cloud icon of a live search result downloads without opening; the patient's page can be pulled to refresh. Settings can no longer be shared from the login page (share and import stay in Settings).
- **Smaller changes:** live mode default in `<sync live-mode-default>`; deleting data at logout is off by default; offline login is a switch in Settings; Import / Export files say who exported them and from where; a hint for the "patient to identify after" note.

### Performance and code

- **Group sessions** (not benchmarked): the validation of a patient's answers is remembered, a draft is saved only when it changed, and the group form is no longer read back from its own JSON.
- **Code clean-up, no behaviour change:** one `Encounter.isVisit()` instead of eight copies, `const val` constants, about 60 comments that repeated the code removed. 11 unreferenced adapters and 3 layouts removed.
- **Tests:** the useless and duplicated tests were removed (a file that was all commented out, tests that only asked a mock whether it was called, the Activity form test, order-dependent instrumented tests) and the rest regrouped; see `docs/dev/setup/testing.md`. The instrumented suite runs on the emulator and passes.
- **Developer tools and documentation** for Windows, macOS and Linux: `tools/dev.py` (`doctor`, `install`, `logcat`, `reverse`, `hosts`, `adb-restart`) replaces four shell scripts, and the contributor documentation was reorganised. Not checked on macOS and Linux. A five-language user guide with screenshots and PDFs lives in `docs/user-guide/`; the translations were not read by native speakers.

### Follow-ups of the patient-list decision

- At least one patient list must be selected: the sync never downloads patients without a list.
- Login sends one `Authorization` header (it sent two, and the server answered 400).
- Search by identifier or phone.
- Unsaved-changes guard on registration and edit. Its first version read the questionnaire response early, which made the form library drop conditional items: patients were saved without a gender and refused (422). The unit tests did not catch it, the offline create then upload test did.

## Earlier work: dependencies, settings and UI (branch `chore/upgrade-dependencies`)

**Look and feel.** OpenMRS 3 teal palette (light, dark, and a color-blind one), bottom navigation, a redesigned app bar without double titles and a connection strip under it, one dialog look for the 27 old dialogs and one look for messages, simpler location banners, clearer names for the Home cards and screen titles, edge-to-edge screens that pad by the measured app bar, the logo without its white plate, the theme applied at once. Small screens: 320 dp with a 1.3 times font in French and Arabic was checked for Home, Patients and Settings; dialogs wrap their buttons; the first-run tour is mirrored for right-to-left. Home, Patients, Settings and Sync keep their content in a column of at most 720 dp. Tapped rows now say they are buttons or checkboxes to TalkBack (no TalkBack run).

**Sign-in and sessions.**
- Single sign-on has its own `auth_config.xml` and the session renews itself; the saved session is used when the app is opened again.
- The offline login asks again when the user comes back (with settings for how long) and confirms deleting data; the answer is remembered; the app lock "every time" no longer asks twice at start.
- The login page is disabled while the server cannot be reached, with "Continue without signing in" as the way on; a guest sees an honest connection banner; the side menu shows who is signed in.
- Logging out works with the server out of reach; changing the location with the server out of reach no longer crashes.
- The location is the user's own, with a "Remember my location" setting; choosing no location, or no patient list, is respected and asked only once.
- A session that expires shows a strip "Session expired. Sign in" (checked on a device); a message points to SSO when the password is rejected.
- `<support>` and `<diagnostics>` are separate in `app_config.xml`; `patients-since` was removed because it silently never downloaded older patients; `validateAppConfig` checks the configuration before every build.

**Several users on one device.** When data stays at logout a user no longer sees patients another user registered or downloaded, unless a per-user setting allows it.

**Sync.**
- Upload-only and download-only sync; a running sync can be cancelled, and a cancelled sync is "Cancelled", not an error; the buttons are off while the server cannot be reached.
- Patients of a list just ticked are downloaded at once; the list screen is about 10 times faster and says what is going on.
- Fixed: a download that crashed on a resource without `meta.lastUpdated` and never finished; encounters uploaded without their provider (`provider_id` cannot be null); closing or reopening a visit failed at sync (the update went as a PATCH).
- The automatic sync can be delayed from the strip, and run only on Wi-Fi or when the battery is not low; sync history totals are what was done.
- Live mode: patients are found on the server (from 3 characters, after a 450 ms pause) and what is saved is sent a moment later.
- Import / Export when a device cannot sync; an audit trail and a better Send diagnostics (time range, sizes, crash frames, required password, **Download** as well as Send).

**Patients and forms.**
- Registration in pages, with the review opening only when the mandatory fields are filled and no "Submit anyway"; a patient can be registered without a location; the profile shows all the details with tap to call.
- Identify later needs a signed-in user online, with a way out when the patient is not on the server; patients to identify show before syncing.
- Encounters open read-only with a clearer Edit button, also when their form is not on the device; the start and end of a visit can be edited; visits are created automatically or by the user (Settings > Visits).
- Faster forms (four costs found by profiling the emulator); a pending group session is shown in its form's row and several can be chosen from a popup; the group session tabs follow the theme.
- Patient list: sort and "Show more" (it showed only the first 100 patients), a search box in Settings, a Home summary of the patients on the device and what is not uploaded.
- Bundled questionnaires (the 26 published by the server) and patient lists scoped by location; no list, no patient data.

**Settings.** Saved as they change, with a Back button; a reset to defaults from the top bar; a "Live mode" section; one "Forms" section with "Use embedded forms only" and favorites; a connection test and **Change server**; the settings can be shared with a QR code (export and import); "Log out and delete all data" and **Delete patient data** without logging out.

**Build and platform.** Stable Open Health Stack (FHIR engine 1.2.0, data-capture 1.3.1 from Google Maven, no GitHub token); a version catalog; release signing from the environment (`OPENMRS_KEYSTORE...`) and a shrunk release run against the server; database squashed to a baseline: `AppDatabase` is version 1 with no migrations, **a device with an earlier build must be uninstalled first**, and the next schema change after real devices hold the baseline needs a version bump, a migration and its test (`docs/dev/architecture.md`). Dead code such as the debug builder that accepted every certificate was removed.

## Earlier work: code review follow-ups (branch `chore/upgrade-dependencies`)

- HTTP logging no longer prints request bodies, tokens or cookies in every build; stack traces go to Timber; an unused dependency and the leftover TODOs are gone.
- 15 force unwraps, `runBlocking` where a coroutine was already running and `collectAsState()` calls were replaced; one base OkHttp client; 13 ViewModels take injected dispatchers; the token watch is one coroutine.
- Large files were split without changing code (`SettingsScreen`, the session end of `MainActivity` moved to `SessionCleaner`), `extensions/` was regrouped into packages, the tools moved to `tools/`, and the form screens share their progress bar and touch blocker.
- Verified on the final state of the branch: `spotlessCheck`, the unit tests, `lintDebug` and the emulator (SSO sign-in, location, registration).
